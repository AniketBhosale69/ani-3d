# ANI3D — deployment

Static site + Cloudflare Pages Functions + D1. No build step.

```
index.html, gallery-*.html, blog.html, …   static pages
admin/index.html                           admin dashboard (password-protected)
functions/api/videos.js                    GET /api/videos      public, read-only
functions/api/posts.js                     GET /api/posts       public, published only
functions/api/admin/*                      authenticated CRUD
schema.sql                                 D1 tables
seed.sql                                   generated by tools/export-supabase.mjs
```

---

## 1. Create the database

```bash
npx wrangler d1 create ani3d
```

Copy the printed `database_id` into `wrangler.toml`, replacing `local-placeholder`.

```bash
npx wrangler d1 execute ani3d --remote --file=schema.sql
npx wrangler d1 execute ani3d --remote --file=seed.sql
```

`seed.sql` already contains all 16 rows migrated out of Supabase (8 classic
videos, 6 out-of-frame, 2 blog posts). To regenerate it:

```bash
SUPABASE_KEY=<anon-key> node tools/export-supabase.mjs
```

---

## 2. Set the secrets

Two are required. The app returns 500 on login without them.

```bash
npx wrangler pages secret put ADMIN_PASSWORD --project-name=ani-3d
npx wrangler pages secret put SESSION_SECRET --project-name=ani-3d
```

- `ADMIN_PASSWORD` — what you type at `/admin`. Use something long; this is the
  only thing standing between the internet and your catalogue.
- `SESSION_SECRET` — signs the session cookie. Never type this anywhere; just
  generate one and paste it:

  ```bash
  openssl rand -hex 32
  ```

Changing `SESSION_SECRET` immediately invalidates every existing login, which is
how you kick yourself out of a session you no longer trust.

You can also set both in the dashboard under **Settings → Environment variables
→ Secrets** (encrypted, not plain variables).

---

## 3. Bind D1 to the Pages project

Dashboard → your Pages project → **Settings → Bindings → D1 database**:

- Variable name: `DB`
- Database: `ani3d`

Add it for **both** Production and Preview.

---

## 4. Deploy

Push to `main` — Pages builds automatically (framework preset **None**, no build
command, output directory `/`).

Or directly:

```bash
npx wrangler pages deploy . --project-name=ani-3d
```

---

## Local development

```bash
npx wrangler pages dev .
```

Reads secrets from `.dev.vars` (gitignored) and uses a local SQLite copy of D1.
First time:

```bash
npx wrangler d1 execute ani3d --local --file=schema.sql
npx wrangler d1 execute ani3d --local --file=seed.sql
```

`./run.sh` still works for pure static/CSS work, but it does not serve `/api/*`,
so the galleries and blog will be empty under it. Use `wrangler pages dev` for
anything touching data.

---

## Using the dashboard

Go to `/admin`, enter the password. Sessions last 12 hours.

**Videos** — add/edit/delete across both galleries. `Category` decides which
gallery a video appears in. `Genre` is comma-separated and feeds the gallery
genre filter, so keep spelling consistent — the filter matches exact strings,
and a stray trailing space makes a video invisible under its own genre. The
Content type and Language fields autocomplete from existing rows for this reason.

**Blog posts** — new posts default to **draft** and are not reachable from the
public API until you switch them to published. The slug is derived from the
title if you leave it blank; changing it later breaks any existing link. Content
is raw HTML, rendered as-is on the blog page — only paste markup you trust.

## Security notes

- The database is reachable only through the Worker. Unlike the Supabase setup,
  no key is shipped to browsers, and the public endpoints can only SELECT.
- Everything under `/api/admin/*` is gated by `functions/api/admin/_middleware.js`,
  so a route added later is protected by default.
- Session cookies are `HttpOnly; Secure; SameSite=Strict`, signed with HMAC-SHA256.
  Password and signature comparisons are constant-time.
- `/admin/index.html` itself is public — it is just a login shell containing no
  data. Only the API is protected. If you want the page hidden too, put a
  Cloudflare Access policy in front of the `/admin` path.
- Login has a fixed 500 ms delay on failure but **no rate limiting or lockout**.
  A long random password is doing the real work here. If you want brute-force
  protection, add a Cloudflare WAF rate-limiting rule on `/api/admin/login`.

## Decommissioning Supabase

Once the site is live on D1 and you have verified both galleries and the blog:

1. Take a final export (`tools/export-supabase.mjs`) and keep `seed.sql` somewhere safe.
2. Rotate or delete the Supabase anon key — it was committed to this repo's
   history and is permanently compromised.
3. Delete the `videos`, `outframe_videos` and `blog_posts` tables, or pause the
   project entirely.

Until step 2, treat that key as public.
